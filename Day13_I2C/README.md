# 📅 Day 13 – I²C (Inter-Integrated Circuit) Communication in 8051

Welcome to **Day 13** of my **Embedded Firmware Engineer Learning Journey**.

Today, I learned **I²C (Inter-Integrated Circuit)**, a two-wire synchronous serial communication protocol widely used in embedded systems for communication between microcontrollers and external peripherals such as EEPROMs, RTC modules, sensors, and displays.

Unlike SPI, I²C uses only two wires (SDA and SCL) and supports multi-master, multi-slave communication using device addressing, making it ideal for systems with many low-speed peripherals.

## Part 3 – I²C Signals

I²C uses two communication lines:

| Signal | Full Form | Function |
|--------|-----------|----------|
| SDA | Serial Data | Carries data between Master and Slave |
| SCL | Serial Clock | Clock signal generated by Master |

---

# 🔄 I²C Communication Process

1. Master generates a Start condition (SDA falls while SCL is high).
2. Master sends the 7-bit slave address + R/W bit.
3. Addressed slave responds with an ACK bit.
4. Data is transferred one byte at a time (MSB first).
5. Receiver sends ACK after each byte, or NACK on the last byte.
6. Master generates a Stop condition (SDA rises while SCL is high) to end communication.

---

# 🧠 I²C Features

- Two-wire communication (SDA, SCL)
- Half-duplex data transfer
- Multi-master, multi-slave support
- Device addressing (7-bit / 10-bit)
- Open-drain lines requiring pull-up resistors
- Simple hardware structure with fewer pins than SPI

# 🧠 I²C Registers Concept

Since classic 8051 does not contain I²C hardware, I²C is controlled using GPIO.

Important registers used:

## Port Registers

Used for controlling I²C pins.

```c
P1 = data;
```

---

## Data Direction

Controls input/output operation using sbit declarations.

Example:

```c
sbit SDA = P1^0;
sbit SCL = P1^1;
```

---

# ⚙ Software I²C Initialization

```c
void I2C_Init()
{
    SDA = 1;
    SCL = 1;
}
```

---

# 🔄 I²C Data Transmission

Transmission steps:

1. Generate Start condition.
2. Send 8 bits (MSB first) through SDA, clocked by SCL.
3. Release SDA and read ACK/NACK on the 9th clock pulse.
4. Repeat for additional bytes if needed.
5. Generate Stop condition to end transaction.

Example:

```c
bit I2C_WriteByte(unsigned char dat)
{
    unsigned char i;
    bit ack;

    for(i = 0; i < 8; i++)
    {
        SDA = (dat & 0x80) ? 1 : 0;
        dat <<= 1;

        SCL = 1;
        I2C_Delay();
        SCL = 0;
        I2C_Delay();
    }

    SDA = 1;
    SCL = 1;
    I2C_Delay();
    ack = SDA;
    SCL = 0;

    return ack;
}
```

---

## Slave Device (e.g., EEPROM 24C02)

| Slave Pin | Connect To |
| --------- | ---------- |
| SDA       | Master SDA |
| SCL       | Master SCL |
| A0/A1/A2  | Ground (address select) |
| WP        | Ground     |
| VCC       | +5V        |
| GND       | Ground     |

> ⚠️ Both SDA and SCL require pull-up resistors (4.7kΩ) to VCC since I²C uses open-drain outputs.

# 📌 Key Takeaways

* I²C is a synchronous, half-duplex serial communication protocol.
* I²C uses only two lines: SDA and SCL.
* I²C follows Master-Slave architecture and supports multiple masters/slaves.
* Master generates the clock signal on SCL.
* SDA must only change while SCL is LOW, except during Start/Stop conditions.
* The 9th clock pulse is reserved for ACK/NACK handshaking.
* Classic 8051 does not have built-in I²C hardware.
* I²C can be implemented using GPIO pins (Bit Banging).
* I²C uses fewer wires than SPI but is generally slower.
* I²C is widely used for EEPROM, RTC, sensors, and display modules.
